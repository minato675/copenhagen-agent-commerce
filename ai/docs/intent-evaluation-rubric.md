# 구매 의도 분석 판정 기준 v2

이 문서는 모델 출력의 정답 여부를 판정하는 기술 명세다. 개인 계획이나 실행 결과는 포함하지 않는다.

## 입력과 기준의 버전

`fds-intent-eval-v1`의 입력·기대 라벨·Mock 응답·해시는 변경하지 않는다. 기존 저장 관측값도 그대로 사용한다. 채점기는 `fds-intent-grader-v1`과 `fds-intent-grader-v2`를 선택할 수 있다. v2는 고정 v1 평가셋에만 적용하며 규칙 해시를 보고서에 남긴다. 신규 평가셋에는 별도 판정 기준이 필요하다.

## 판정 경계

* MATCH: 요청 상품과 명시된 의미 조건을 충족하며 판정을 막는 미해결 정보가 없다. 입력에 없는 조건이나 속성을 새로 요구하지 않는다. 필수 조건이 없다는 것은 조건 정보가 누락됐다는 뜻이 아니다.
* MISMATCH: 요청과 주문 사이의 확정된 의미 불일치가 있다. 필수 브랜드·조건 위반, 미요청 상품 등 관련 주문/항목을 정확히 지목한다. 요청 자체의 상충 조건을 임의로 하나 선택해 위반을 확정하지 않는다.
* UNKNOWN: 확정 불일치는 없고 필요한 정보 부족·상충·대체 확인이 남아 있다. 미지정 값을 주문에서 채워 확정하지 않는다. 미해결 정보와 별개의 명확한 불일치가 함께 있으면 MISMATCH와 확인 요청을 함께 보존한다.
* 수량·금액·통화의 최종 정책 집행은 BE 범위다. 미지정 수량이나 모호한 예산은 확인 필요로 전달하지만 비교 입력에서 제외된 숫자를 다시 요구하거나 예산 초과·수량 불일치를 계산하지 않는다.

## 추출 필드

모델명은 상품명에 보존하고 브랜드로 바꾸지 않는다. 필수 브랜드·조건과 참고 선호를 구분한다. 미제공 값은 null을 허용하되 명시된 값·상충 조건을 누락해서는 안 된다. 근사 예산과 최대 예산, 통화 최소 단위를 구분한다.

v2의 유한한 허용 차이는 다음과 같다. 다른 필드의 오류를 함께 허용하지 않는다.

| 사례 | 추가로 허용하는 표현 | 근거 |
|---|---|---|
| fds-19 | 상품명 키보드·수량 2·브랜드 null을 유지한 채 category=null | 카테고리는 nullable이며 명시 상품명만으로 종류를 알 수 있음 |
| fds-16/23 | explicit_conditions=["2개만"] | 요청에 있는 수량 한정 표현의 중복 보존이며 새로운 의미 제약이 아님 |

누락과 null, bool과 정수, 정수와 숫자 문자열은 구분한다. 원래 평가 대상이 아닌 필드를 정답으로 간주하지 않으며 필드 일치율을 모든 자연어 추출의 정확도로 해석하지 않는다.

## 사유와 확인 사항

v1 표현을 유지하면서 아래 완전한 조합을 추가 허용한다. 이 사례들은 요청 전체의 정보 부족이므로 관련 상품 참조는 빈 배열이다. 특정 주문 상품의 속성 누락·불일치는 기존의 정확한 order_id/item_id를 요구한다.

| 사례 | 사유 코드 / 차원 | 확인 코드 |
|---|---|---|
| fds-04 수량 미지정 | INSUFFICIENT_DATA / QUANTITY | PROVIDE_MISSING_DATA 또는 CLARIFY_INTENT |
| fds-05 통화 미지정 | INSUFFICIENT_DATA / BUDGET | PROVIDE_MISSING_DATA 또는 CLARIFY_INTENT |
| fds-06 예산 종류 모호 | INTENT_UNCERTAIN / BUDGET | CLARIFY_INTENT |
| fds-17 상품 미지정 | INSUFFICIENT_DATA / PRODUCT | PROVIDE_MISSING_DATA |
| fds-17 상품 미지정 | INTENT_UNCERTAIN / PRODUCT | CLARIFY_INTENT |

v2는 하나의 허용 조합과 일치해야 한다. 사유·확인 순서는 무관하지만 중복·무관한 추가 사유·잘못된 상품 참조·허용되지 않은 사유/확인 조합은 실패다. 라벨 정확도, 사유, 확인 코드, 전체 조합, 추출 필드, 전체 사례 통과율을 각각 표시한다. 라벨은 맞지만 설명이 틀린 응답을 구분할 수 있다.

## 개선 전후 비교

저장된 동일 응답을 두 채점기로 재채점해 기준 변경 효과를 먼저 확인한다. 모델 개선 전후 비교에는 동일 채점기를 사용한다. 실패·미실행을 라벨/필드 분모에서 임의 제거하지 않는다. 새 채점기로 점수가 상승했다고 모델이 개선됐다고 보고하지 않는다.

실제 응답 재평가·독립 데이터 검증은 별도 실행이다. 기본 테스트의 합성 응답 통과는 실제 모델 성능이 아니다. 작업별 평가, 사람 판정과의 정합성 및 대표 사례·경계 사례·공격 사례 포함 원칙은 [OpenAI 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)을 따른다.
