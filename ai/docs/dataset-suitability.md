# 로컬 Feature 데이터 적합성 점검

`copenhagen_fds.data_audit`는 보유 CSV의 스키마·SHA-256·집계와 일부 명시된 관계만 확인한다. 원시 행이나 셀 값은 출력하지 않고, 데이터를 수정·분할·학습하지 않는다. CLI의 성공은 집계가 끝났다는 뜻이며 학습 적합 판정이 아니다.

## 재현

`ai/`에서 기존 가상환경을 사용한다. Python 표준 라이브러리만 사용하며 네트워크, API 키, `.env` 또는 별도 패키지 설치가 필요하지 않다.

```powershell
.\.venv\Scripts\python.exe -m copenhagen_fds.data_audit data/fraud_model_features_erd_common.csv
.\.venv\Scripts\python.exe -m pytest -q tests/test_data_audit.py
```

첫 명령은 JSON 집계를 표준 출력으로 보낸다. 성공 종료 코드는 0이고, 파일을 읽을 수 없거나 CSV 형식이 잘못되면 2다. 중복·빈 열 이름, `is_fraud` 열 누락, 행 너비 불일치와 잘못된 인코딩·인용문은 집계 실패다. 비수치·비유한 셀과 잘못된 라벨은 원시값 없이 건수로 남긴다. 라벨은 정확한 문자열 `0`, `1`만 집계하며 공백이나 `0.0`은 임의로 정상 라벨로 변환하지 않는다. 오류 메시지에 파일 경로·원시 셀을 넣지 않는다.

파일 전체를 한 번 읽은 바이트 스냅샷으로 해시와 집계를 함께 계산한다. 현재 파일 크기에 맞춘 도구이며 스트리밍 대용량 분석기는 아니다. 결과에는 열 이름과 집계만 포함되지만, 실제 공유 시에도 파일의 열 이름 자체에 민감정보가 없는지 확인한다.

## 확인된 파일과 집계

| 항목 | 값 |
|---|---|
| 점검 대상 | `ai/data/fraud_model_features_erd_common.csv` |
| Audit 버전 | `erd-common-csv-audit-v1` |
| SHA-256 | `d59aa0c2c3f07e26f3712d33b3dd659bb532871ae8a8fff517ffe511347b4378` |
| 파일 크기 | 21,126,227 bytes |
| 행 / 열 / 라벨 제외 열 | 100,000 / 28 / 27 |
| 정상 / Fraud / 잘못된 라벨 | 91,789 / 8,211 / 0 |
| 빈 셀 / 비수치 / 비유한 셀 | 모두 0 |
| 계정 연령 음수 | 0 |

음수 개수는 열마다 보고하며 그 자체를 오류라고 판정하지 않는다. 예를 들어 `amount_deviation`과 `amount_zscore`는 의미상 음수가 가능하다. 이전 문서의 계정 연령 음수 16,606건은 이 해시의 파일에서 확인되지 않는다. 어떤 처리로 달라졌는지 추정하지 않는다.

| 구조 확인 기준 | 검사 행 | 불일치 행 | 생략 행 |
|---|---:|---:|---:|
| 요일 0~6, 주말은 5·6 | 100,000 | 0 | 0 |
| 시각 0~23, 야간은 22~23·0~5 | 100,000 | **4,132** | 0 |
| 계정 연령은 음수 없는 정수, 신규는 14일 미만 | 100,000 | 0 | 0 |
| 결제수단 5개가 0·1이고 정확히 하나만 1 | 100,000 | 0 | 0 |
| 거래 횟수는 음수 없는 정수, 10분 ≤ 1시간 ≤ 24시간 | 100,000 | 0 | 0 |

이 검사는 로컬 `fraud_feature_spec.csv`의 단순 범주 정의와, 동일 사용자·동일 사건·동일 기준 시점으로 집계했을 때의 시간 창 포함 관계를 확인한다. 필요한 열·유효 수치가 없으면 성공으로 처리하지 않고 생략 건수로 남긴다. 야간 불일치는 현재 열 정의와 명세가 일치하지 않는다는 증거이며 어떤 기준이 옳은지는 이 집계로 결정할 수 없다.

나머지 평균·중앙값·표준편차·비율·로그·clip 등의 원본 계산을 검증한 것은 아니다. 일치한 단순식도 라벨 타당성·학습 가능성·시간 누수 부재를 증명하지 않는다.

## 출처와 시간순 평가에 필요한 근거

| 확인 대상 | 현재 근거 | 결과 |
|---|---|---|
| 원본 출처 | 기존 문서에 공개 후보 이름이 있으나 현재 CSV에 연결되는 다운로드 기록·원본 해시 없음 | 미확인 |
| 사용 조건 | 현재 파일에 적용되는 출처별 이용 조건·허가 증빙 없음 | 미확인 |
| 변환 과정 | 기존 문서는 77개에서 27개로 선별했다고 설명하나 현재 `ai/`에 원본 파일·생성 스크립트 없음 | 미확인 |
| 라벨 근거 | `is_fraud` 0·1만 존재, 판정 주체·규칙·차지백·확정 시점 없음 | 미확인 |
| 사용자별 연결 | `user_id` 등 사용자 식별 열 없음 | 재구성 불가 |
| 사건 중복·연결 | 거래·이벤트 ID 없음 | 중복 사건인지 확인 불가 |
| 사건 시각 | 시간대·요일만 있으며 개별 거래 발생 시각 없음 | 시간순 정렬·재생 불가 |
| 이용 가능 시각 | 수집·반영·이용 가능 시각 없음 | 평가 당시 알려진 이력인지 확인 불가 |
| 라벨 이용 가능 시각 | 라벨 확정·관측 시각 없음 | 지연 라벨의 미래 누수 확인 불가 |
| 원시 통화 | `amount_krw` 이름은 있으나 통화·환율·환율 기준 시각 없음 | 변환 재현 불가 |
| 서비스 Feature 일치 | 명세에 다수 원천이 `MOCK`로 표시됨 | 실제 BE 제공 데이터와 동일함을 미검증 |

CLI의 `recognized_replay_columns`는 명시한 열 이름 후보가 있는지만 출력한다. 열이 있다고 값의 형식·의미·유일성·시간 정합성이 검증되는 것은 아니다. 출력의 `evidence_status`는 출처·사용 조건·라벨·Feature 생성·시점 정합성 모두 `NOT_VERIFIED`로 유지한다.

로컬 Feature 명세에는 다음 확인 사항도 남아 있다.

- `amount_krw`는 Mock 환율 변환을 언급하지만 환율표·버전·시점이 없다.
- `amount_clipped`는 학습 구간의 경계를 사용한다고 설명하지만 실제 경계값과 학습 구간을 알 수 없다.
- 비율·표준화 식의 `epsilon` 값이 명시되지 않는다.
- 일부 이력은 `payments`, 일부는 `authorization_sessions`를 원천으로 설명한다. 서로 다른 사건 정의를 같은 거래 수로 취급할 수 없다.
- `user_avg_hour_prev`의 단순 시각 평균과 `hour_deviation` 정의는 자정 경계의 순환 성질을 어떻게 처리했는지 별도 확인이 필요하다.
- `FINAL_MODEL`, `MCP 생성 가능`은 기존 명세의 분류이며 실제 학습·서빙 계산 일치의 증거가 아니다.

현재 CSV의 행 순서, 시간대·요일, 집계된 거래 횟수로 없는 사용자 ID·원시 시각·라벨 확정 시각을 복원하지 않는다. 임의 ID를 붙이거나 날짜를 합성해 실제 시간순 성능으로 제시하지 않는다.

## 사용 구분

**학습용 최종 선정은 보류한다.** 출처·사용 조건·라벨 생성 근거를 확인한 뒤에도, 실제 BE 입력과 계산식이 일치하는지와 데이터 분할 시 미래 정보가 섞이지 않는지를 따로 검증해야 한다. 추후 실험을 진행한다면 결과를 이 데이터 출처와 생성 조건에 한정하고 실서비스 정확도로 확대하지 않는다.

**시나리오용으로는 열 구조와 검증 항목을 참고할 수 있다.** 원시 행을 복제하는 대신 명시적인 가상 사용자·사건 시각·이용 가능 시각을 가진 독립 합성 이력을 구성한다. 그 결과는 관측 범위·계산·Cold Start 분기를 검증하는 결과다. 합성 라벨을 이용한 높은 성능을 실거래 사기 탐지 근거로 표시하지 않는다.

**시간순 개인·집단 프로필 검증에는 현재 표를 사용하지 않는다.** 평가 시점 이전 발생한 사건 중 그때까지 이용 가능했던 이력만 선택할 수 있는 원시 자료가 필요하다. 프로필의 관측 표본 수·참조·시각이 있어도 원시 이력의 누수를 자동으로 증명하지 않는다. 학습·검증·평가 분할은 시간 관계와 사용자·이벤트 중복, 지연 라벨을 확인해야 하며 무작위 Stratified Split만으로 대체하지 않는다.

이 문서는 적합성 근거를 기록하며 원시 데이터, 개인 계획 또는 상태 추적을 Git에 등록하지 않는다. 기존 [선정 문서](selected_dataset.md)의 사용 범위도 이 근거에 맞춰 제한한다. Core·Pay의 원천 수집·조회·결제 실행은 담당 서비스의 책임이며, 이 점검 도구가 구현하지 않는다.
