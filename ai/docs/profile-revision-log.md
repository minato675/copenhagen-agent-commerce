# 구매 정정 이력과 보관 상태

`contracts/profile_updates.py`는 개인·집단 통계 스냅샷에 구매별 수정 번호와
처리한 사건 영수증을 붙이는 불변 입력 계약이다. DB 테이블이나 결제 API를 만들지 않는다.

`initialize_profile_update(snapshot)`은 완전한 이력으로 작성된 기존 스냅샷을
초기 상태로 바꾼다. 기존 구매의 수정 번호는 0이며, 새 구매는 1부터 시작한다.
`state_version`은 스냅샷·수정 상태·영수증 내용의 SHA-256으로 결정한다.

`ProfileUpdateEvent`의 UPSERT는 구매 한 건의 **완전한 LearningSample 교체**다.
금액을 누적하는 명령이 아니다. REMOVE는 해당 구매를 제거하고 삭제 표식을 남긴다.
각 사건에는 고유 `event_id`, 구매 식별자, 수정 번호, 직전 내용 해시,
`available_at`, 변경 이유가 필요하다. 표본 해시는 조회 기준 시점만 제외하며,
확인 결과·주문 버전·피처 값·결측·원천 식별자는 포함한다.

| 상황 | 처리 |
|---|---|
| 같은 사건 재전달 | 영수증으로 중복 처리 |
| 같은 수정 번호·같은 최종 내용 | 중복 처리, 새로운 사건 ID는 영수증 추가 |
| 같은 사건 ID·다른 내용 또는 같은 수정 번호·다른 내용 | 배치 전체 거부 |
| 낮은 수정 번호의 지연 전달 | STALE, 최신 내용을 유지 |
| 배치 내부 순서 역전 | 구매별 수정 번호 순으로 적용 |
| 다음 번호가 아닌 수정 또는 직전 내용 불일치 | 각각 전체 재생 필요 또는 충돌 거부 |
| 기준 시점보다 미래에 알려지는 사건 | DEFERRED_FUTURE, 저장하지 않음 |
| 현재 평가 중인 구매 | DEFERRED_CURRENT, 저장하지 않음 |
| 이미 보관 범위를 벗어난 사건 | IGNORED_EXPIRED |

보류 사건은 적절한 다음 기준 시점에 호출자가 다시 전달해야 한다. 이 모듈에는
큐가 없다. `available_at`은 실제 정보 가용 시점이며 네트워크 전달 순서와 다르다.
직전 해시·번호를 모르는 삭제나 정정은 임의로 복구하지 않는다.

INCLUDE뿐 아니라 DEFER·EXCLUDE 표본도 통계 보관 기간에 남는다.
수정 머리는 구매 시각 또는 최근 수정 가용 시각이 보관 범위에 남아 있는 동안 유지한다.
영수증은 사건 가용 시각을 기준으로 같은 기간 보관한다. 따라서 무기한 중복 탐지를
보장하지 않으며, 이미 제거된 오래된 수정 체인이 다시 필요하면 전체 재생해야 한다.

상태 JSON에는 표본이 들어 있으므로 운영 시 프로필과 같은 접근 권한·보관 정책이
필요하다. 합성 데이터의 숨겨진 정답이나 사용자 유형은 입력에 사용하지 않는다.

검증: `python -m pytest tests/learning/updates/test_revision_log.py -v --tb=short`
