# 정상 변화 반영과 오염 방지

`assess_profile_policy(snapshot, observations, config)`는 현재 보관 범위의 학습 표본을
확인 정보의 가용 시각 순으로 재생한다. 사용자·통화별로 별도 기준과 반영 상한을 둔다.
동일한 시각에 알려지는 확인 근거는 함께 공개한 뒤 가용 시각·구매 ID 순으로 처리한다.

미확인·의심·검증되지 않은 거래는 정상 반영 대기열에 들어가지 않는다. 사기 확인도
정상 기준에 들어가지 않는다. 이들은 후속 정상 확인이 제공되어야 다시 후보가 된다.

정상 확인 후보의 반영 조건은 다음과 같다.

1. 비교 기준이 부족하면 검증된 정상 표본으로 초기 기준을 만든다.
2. 이미 반영된 최근 또는 장기 기준과 맞으면 반영할 수 있다.
3. 급격한 변화면 같은 사용자에게서 비슷한 변화가 확인된 구매 수·날짜 수가 설정에
   도달해야 한다. 아직 알려지지 않은 확인이나 의심 거래는 이 근거에 포함하지 않는다.
4. 위 조건을 만족하더라도 사용자별 날짜당 반영 상한을 넘으면 DAILY_LIMIT으로 보류한다.

단일 날짜에 많은 거래를 반복해도 여러 날짜의 습관 변화로 인정하지 않는다. 서로 크게
다른 극단값도 같은 변화의 근거로 묶지 않는다. 같은 조건을 가진 정상 확인 표본은
아직 정책상 보류 중이어도 변화의 근거가 될 수 있다. 이 경우 모두 독립된 정상 확인이 필요하다.

새 근거 도착과 한국 시간 자정마다 보류 후보를 다시 살핀다. 상한만으로 보류한 후보는
다음 날의 여유 한도로 반영할 수 있다. 같은 기준 시각에서 호출을 반복하거나 입력 순서를
바꾸어도 한도를 추가로 받지 못한다. 단발성 정상 예외는 반복된 습관 변화 조건을 만족하지
못하면 계속 보류될 수 있다. 정책상 보류는 그 거래가 사기라는 뜻이 아니다.

원래 `LearningDecision`을 수정하지 않는다. NORMAL_CONFIRMED/INCLUDE와 정책상의
DEFER/ABRUPT_CHANGE가 동시에 존재할 수 있다. 정상 확인 여부와 통계에 반영할지 여부는
서로 다른 판단이다. 결측 피처를 임의의 정상값으로 채우지도 않는다.

## 재생 범위와 정정

현재 기준 시점에 알려진 최종 확인 결과로 **보관 범위 전체를 다시 재생**한다. 사기로
정정된 거래는 정상 후보에서 빠지므로 철회가 하루 반영 상한에 막히지 않는다.
정정으로 다른 후보의 기준이나 순위가 달라지면 그 후보의 반영 여부도 다시 계산한다.

최근·장기 기간은 기존 통계 설정을 사용하고, 실제 재생 시작은 `replay_from`에 기록한다.
보관 기간이 이동하면 사용할 수 있는 초기 기준과 과거 후보가 달라질 수 있다. 무기한
과거의 판단을 고정하는 정책이 아니며, 전체 재생 비교도 같은 보관 경계를 사용한다.
이 계산은 보관 이력의 재현성을 우선하며 상수 시간 온라인 갱신이나 운영 처리량을 보장하지 않는다.

검증: `python -m pytest tests/learning/policy/test_admission.py -v --tb=short`
