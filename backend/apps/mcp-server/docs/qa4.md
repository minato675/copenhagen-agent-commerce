## 실행과 기존 터널 유지

QA3와 QA4는 **127.0.0.1:8093**을 공유한다. 두 서버를 동시에 실행하지 않는다.
QA3 서버만 종료하고 QA4를 시작하면 같은 `/mcp` 주소를 사용하는 기존 터널은 유지할 수 있다.

```powershell
# 저장소 루트에서 실행. QA3가 실행 중일 때만 첫 명령을 사용한다.
backend/apps/mcp-server/scripts/stop-qa.ps1 -Stage 3
# 기존 QA3의 catalog.json을 build/qa4/catalog.json으로 복사한다.
# cart.json은 QA3 종료 후 필요한 경우만 복사한다. 기존 QA4 원장을 덮어쓰지 않는다.
backend/apps/mcp-server/scripts/start-qa.ps1 -Stage 4
```

미리보기: <http://127.0.0.1:8093/qa>. QA4만 `X-Copenhagen-Qa: handoff-mock`을 반환하며
카탈로그·장바구니·연결·인계 Tool 10개만 노출한다. 임시 QA 신원은 4시간 후 만료되므로
`stop-qa.ps1 -Stage 4` 후 서버를 재시작한다. 이때도 살아 있는 터널 콘솔은 그대로 둔다.
새 Tool/리소스를 반영하려면 ChatGPT 앱 설정에서 도구 새로고침 후 새 대화를 사용한다.

터널이 종료된 경우에만 기존 tunnel ID로 `start-qa-tunnel.ps1 -Stage 4`를 실행한다.
Secure Tunnel은 MCP를 전달하며 휴대폰에 로컬 `/qa` 웹사이트를 공개하지 않는다.

## 로컬 상품·판매처 데이터

판매처 ID는 `qa-a`·`qa-b`·`qa-c`를 유지하고 표시명은 각각 **노르드 마켓**·**하운 스토어**·
**벨루아 셀렉트**를 사용한다. 가격 노이즈와 판매처 이름은 로컬 QA 설정이며 실제 판매처 정보가 아니다.

제공 SQLite의 르무통 운동화(`danawa:42339224`)는 `product_variants`가 없고 색상·사이즈 배열도 비어 있다.
본문의 라이트블루와 가격 비교 링크는 구매 가능한 옵션 조합의 근거로 사용하지 않는다.
대신 `scripts/qa-product-options.json`에서 라이트블루·다크네이비·아이보리와 230~280mm(10mm 간격)를
조합한 **18개 로컬 옵션**을 제공한다. 이 조합과 판매 가능 상태는 합성 값이다.
원본 옵션이 있으면 항상 우선하며 로컬 catalog의 `optionSource`로 `SOURCE_VARIANTS`·`LOCAL_FIXTURE`·
`NONE`을 구분한다. 운영 Core 옵션 계약에는 이 fixture를 포함하지 않는다.

importer는 기본으로 위 fixture를 읽는다. `--source-options-only`를 붙이면 합성 옵션을 제외하고,
`--option-fixtures "C:\경로\qa-product-options.json"`으로 같은 형식의 다른 로컬 fixture를 지정할 수 있다.
데이터를 갱신할 때 importer를 다시 실행하고 생성된 `build/qa2/catalog.json`을 QA4의
`build/qa4/catalog.json`으로 복사한 뒤 QA4 서버만 재시작한다. 기존 `cart.json`은 덮어쓰지 않는다.

재고가 미확인인 값은 importer의 `qa-stock-v1` 로컬 fixture로 채운다. 상품·판매처 또는 옵션 ID의
고정 해시로 판매중/품절을 결정하므로 재생성해도 동일하며, 원본의 알려진 판매중·품절·단종과 구매 제한은
보존한다. 옵션이 있는 상품의 미확인 비교 재고는 옵션의 판매 상태를 집계한다. 판매처가 품절/단종이면
옵션 선택으로 판매중이 되거나 장바구니에 담기지 않는다. 보강한 로컬 상품에는 `inventoryFixture`를 기록한다.
`--source-stock-only`로 이 보강을 끌 수 있다. 합성 재고는 실제 Core 데이터에 적용하지 않으며
재고 수량은 생성하지 않는다. 이 모드에서도 실제 재고와 최종 구매 가능 여부는 주문 전에 Core에서 확인해야 한다.

## 런타임 키 반복 입력 줄이기

터널의 환경변수 이름은 `CONTROL_PLANE_API_KEY`이다. 이 실행기는 `OPENAI_API_KEY`를 사용하지 않는다.
우선순위는 실행 프로세스의 환경변수 → `backend/apps/mcp-server/.env.local` → 보안 입력이다.
파일은 사용자가 직접 만들고 다음 한 줄에 실제 런타임 키를 입력한다. 값은 채팅에 보내지 않는다.

```dotenv
CONTROL_PLANE_API_KEY=YOUR_RUNTIME_KEY
```

`.env.local`은 현재 저장소의 Git ignore 대상이다. 따옴표 사용은 가능하며 줄 끝 주석은 지원하지 않는다.
다른 파일은 `-EnvFile`로 지정할 수 있다. 이 파일은 이 터널 스크립트가 읽는 로컬 설정이며
Spring 서버나 이미 실행된 다른 터미널에 자동 적용되지는 않는다. 스크립트는 해당 키만 파싱하고
표현식을 실행하지 않으며 값을 출력하지 않는다. 종료 시 이전 프로세스 환경변수로 복원한다.
파일에 저장하면 키는 로컬 디스크에 평문으로 남는다. 파일 저장을 원하지 않으면 기존 보안 입력을 쓴다.

```powershell
backend/apps/mcp-server/scripts/start-qa-tunnel.ps1 -Stage 4 `
  -TunnelId 'YOUR_EXISTING_TUNNEL_ID' -ClientPath 'PATH_TO_OFFICIAL_TUNNEL_CLIENT.exe'
```

기존 터널이 살아 있는 동안은 위 명령을 다시 실행하지 않는다. 필요한 권한은 Tunnels Read + Use이다.
[OpenAI 공식 Secure Tunnel 문서](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).

## 화면 동작과 제한

1. 상품을 **동일 판매처**로 담고 장바구니의 `구매 진행`을 누른다.
2. READY는 인계 준비만 의미한다. 별도 `QA 링크 열기` 버튼을 눌러 외부 링크를 연다.
3. QA 목적지는 `https://developers.openai.com/plugins#purchase-…`이다. 공개 테스트 참조만 전달한다.
   실제 앱·로그인·결제·주문 생성 성공을 의미하지 않는다. 리다이렉트 허용 origin도 이 도메인으로 한정한다.
4. 요청 유실·UNKNOWN에는 widgetState에 보존한 **같은 요청/키**로 확인한다. 중복 클릭을 직렬화한다.
   READY 요청도 복원 후 장바구니 조회 시 서버에 자동 재확인하며 저장된 링크 자체를 신뢰하지 않는다.
   이 복구는 새 구매 요청이나 링크 열기를 실행하지 않는다. 실패 시 장바구니·상품 상세의
   `이전 구매 요청 확인` 버튼으로 재시도한다. 미확정 장바구니 변경은 `장바구니 변경 결과 확인`을 사용한다.
   확인된 READY 이후 장바구니가 변경되면 이전 요청·링크를 정리해 다음 추가·변경·삭제를 막지 않는다.
   UNKNOWN이나 통신 실패의 요청은 임의로 지우지 않고 같은 키로 결과를 확인한다.
5. 빈 장바구니·다중 판매처·버전/키 충돌·10분 만료에는 다음 행동을 안내하고 링크를 제공하지 않는다.
   새 인계는 사용자가 장바구니에서 다시 진행할 때만 생성한다.
6. 앱 열기 거부/취소는 같은 링크를 재사용한다. 로그인·미설치 도움말은 안내이며 감지 결과가 아니다.
   로컬 미리보기의 Mock 시나리오 선택기는 안내 문구만 바꾼다. 실상태 전이를 위조하지 않는다.

운영 기능은 기본 비활성이다. 실제 적용 시 `CorePurchaseHandoff` 어댑터와
`mcp.handoff.enabled`, 별도 `write-scopes`, 합의된 HTTPS 고정 `link-base`를 설정해야 한다.
Core 응답의 소유자/연결/요청 echo·스키마·상태 조합·만료·링크를 검증하고 사용자 문맥 필드는 제거한다.
공유 Core·Pay·Merchant·Mobile 코드는 이 Task에서 변경하지 않는다.
