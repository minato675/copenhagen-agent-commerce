# Story 433: 독립 카드 대기 경험

기준: Story 432가 병합된 develop 944b95f. 검색·상세·장바구니·구매 카드는 기존 결과를 유지하며 후속 도구가 새 카드를 생성한다. 단일 화면 전환이나 전역 장바구니 배지를 다시 추가하지 않는다.

## 이벤트 계약 (Task 440)

설치된 @modelcontextprotocol/ext-apps 2.0.0의 app.d.ts에서 확인한 공개 이벤트는 ontoolinputpartial, ontoolinput, ontoolresult, ontoolcancelled이다. 부분 입력은 인자 전달이며 판매처 조회 완료율이 아니다. ui/message 응답은 호스트의 메시지 수락이지 장바구니 변경 완료가 아니다.

| 확인된 신호 | 표시 |
| --- | --- |
| 위젯 생성·도구 입력 | 준비 중, 회전 원과 초기 스켈레톤 |
| prepare_cart 호출 | 권한 확인, 정지된 원·동의 안내 |
| ui/message 대기 | 새 카드 요청 중, 회전 원 |
| 8초 대기 | 지연 안내, 임의 진행률 없음 |
| 메시지 수락 | 요청 전달됨, 완료 체크 (서버 작업 성공이라는 표현 금지) |
| 도구 결과 | 카드 렌더링, 스켈레톤 제거 |
| 인증 필요·실패·중단 | 회전 정지, 선택·기존 결과 보존 |

최초 검색 도구가 완료될 때까지 호스트가 위젯을 만들지 않으면 이 위젯은 그 이전 진행 상태를 표시할 수 없다. MCP 서버의 progress 알림이 ChatGPT 위젯으로 전달된다는 실행 증거는 없다. 이 구현은 확인된 UI 이벤트 기반 대체 경로이며 서버 스트림 구현/실제 호스트 검증 완료로 주장하지 않는다.

## 카드별 상호작용 (Task 441/442)

- 원형 표시에는 가짜 퍼센트나 확인하지 않은 서버 단계를 넣지 않는다.
- 요청 식별 세대로 이전 타이머·완료가 새 상태를 덮지 못하게 한다.
- 인증 확인부터 메시지 전달까지 같은 카드의 버튼과 입력을 잠근다. 실패하면 잠금을 해제한다.
- 메시지 응답은 15초까지만 기다리며, 늦은 수락을 성공으로 바꾸지 않는다.
- 사용자의 최신 결정에 따라 장바구니 새로고침·동일 요청 재전달 블록을 제공하지 않는다. 장바구니는 필요할 때 대화로 요청한다.
- 내부 멱등 키 및 변경 요청 보관은 유지한다. 응답이 불명확해도 새 키로 자동 재실행하지 않는다.
- 초기 스켈레톤은 결과를 받은 후 사라지며 실패·취소에서도 제거된다. 이미 받은 결과는 로딩 화면으로 대체하지 않는다.
- aria-live는 단계 변경만 안내하고 매초 시간을 읽지 않는다. 모션 감소 설정에서는 원 회전을 멈춘다.

## 검증 경계 (Task 443)

로컬 fixture와 UI 단위 테스트는 실제 ChatGPT OAuth·음성·EC2 배포 검증을 대체하지 않는다. 배포 이후 도구 새로고침, 새 카드 생성, 동의 취소·토큰 만료, 실제 지연 구간 측정은 별도로 확인한다. 결제 완료 여부는 기존 구매 상태 도구가 반환한 상태만 사용한다.

## 후속 UX 후보

1. 높음: 실제 ChatGPT 환경에서 요청 전달 후 새 카드 누락 빈도를 측정한다.
2. 중간: 여러 판매처 결과가 늦을 때 부분 결과 노출 가능 여부를 호스트와 함께 검증한다.
3. 낮음: 상품 이미지 대체 표시 비율을 측정해 원본 이미지 품질을 개선한다.
