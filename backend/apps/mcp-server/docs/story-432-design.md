# Story 432 — 대화형 검색과 도구별 독립 쇼핑 카드

## 확정한 흐름

대화 단계마다 새로운 결과 카드를 추가한다. 기존 파랑 `#0f62fe`, 흰색·회색·짙은 글자색, Copenhagen 로고와 IBM Plex Sans KR을 유지한다.

1. **대화로 범위 확정**: 요청이 모호하면 용도·예산·종류 중 중요한 조건 1~2개를 질문한다. 충분히 구체적이거나 즉시 검색을 원하면 추가 질문 없이 실행한다.
2. **검색 카드**: 큰 대표 이미지, 상품명, 확인된 가격, 판매처별 옵션 버튼. 직접 검색 결과와 유사 상품을 분리한다. 물컵 요청에 용도가 맞는 머그컵·텀블러를 함께 검색할 수 있다.
3. **상세 옵션 카드**: 새 카드에 이미지·가격·필수 옵션·재고·배송 정보·수량·담기 버튼을 제공한다.
4. **장바구니 카드**: 판매처별 상품과 수량 변경·삭제, 미확정 값을 구분한 합계, 앱으로 결제 요청 버튼을 제공한다.
5. **구매 요청 카드**: 기존 Core → Pay → 앱 승인 흐름의 요청 접수·상태 조회·알림 재요청. 요청 접수를 결제 완료로 표시하지 않는다.

이전 카드는 이전 조회 결과다. 변경 요청에는 해당 cartVersion을 유지하며, 서버 충돌 시 최신 장바구니 카드에서 다시 결정한다.

## Task와 구현 계약

| S15P21A207-445 | 네 HTML 리소스, 도구별 템플릿 연결, 검색 전 질문 정책 |
| S15P21A207-446 | relatedQueries 최대 2개, 직접/유사 결과 분리·중복 제거·부분 실패 |

- 도구별 `ui.resourceUri`와 `openai/outputTemplate`을 같은 템플릿에 연결한다. 정적 HTML과 사용자 데이터의 권한 검증을 분리하고 기존 전송 계층 인증과 도구별 scope를 유지한다.
- 카드 버튼은 MCP Apps `ui/message` 또는 native `sendFollowUpMessage`로 다음 도구 호출을 요청한다. 현재 카드 내부 `tools/call`만으로 새 대화 카드가 생긴다고 가정하지 않는다. 실제 도구 실행·새 카드 배치는 호스트/모델이 결정한다.
- 장바구니 사용 시 `prepare_cart`로 조회·변경 권한을 함께 확인한다. 담기 전 선택한 옵션·수량을 보관하며 내부 권한 준비의 읽기 결과는 현재 카드를 덮어쓰지 않는다. 기존 요청 시간 제한·계측을 재사용한다.
- 변경 요청은 전달 전에 UUID와 본문을 보관하고 같은 키로만 재전달한다. 이전 카드에서 두 번째 변경은 차단한다. 24시간 경과 또는 보관 시각 누락 시 재전달을 차단하고 최신 상태 확인을 안내한다. 위젯 상태에 토큰을 저장하지 않는다.
- 유사 검색어는 모델이 대화 맥락에서 선택하며 Core에는 개별 query로 전달한다. 의미 벡터 검색이나 모든 동의어를 보장하는 기능은 아니다. 기존 상품 비교 그룹을 합치지 않고 판매처/상품 ID 기준 중복 offer만 제거한다.
- 가격 등 필터를 유지하고 검색어별 커서를 사용한다. 첫 페이지에 최대 2회 순차 추가 호출한다. 유사 조회 장애는 직접 결과를 보존하지만 인증 오류는 숨기지 않는다.

## 디자인과 검증

Zen Shopping 참고 이미지에 맞춰 별도 브랜드 헤더·큰 제목·단계 레이아웃을 제거한다. 검색과 장바구니 모두 같은 가로 상품 카드로 표시하며, 이미지 영역은 1:1 고정 비율에 object-fit: cover로 중앙 크롭한다. 상품명·가격·판매처·행동 버튼만 간결하게 배치한다. 비슷한 상품은 카드의 작은 라벨로 구분한다. 이미지 실패·누락에도 동일한 영역을 유지한다. 키보드 포커스·수평 스크롤·이동 버튼·상태 aria-live를 제공한다.

텍스트나 음성으로 장바구니 조회를 요청하면 get_cart를 직접 호출해 같은 카드 스타일의 장바구니와 결제 요청 버튼을 출력하도록 도구 설명에 명시한다. 음성 인식과 도구 선택은 ChatGPT 호스트가 담당하며 로컬 시안의 ‘장바구니 보여줘’는 발화를 대신하는 테스트 버튼이다.

`ui/preview.mjs`는 운영 `commerce-app.js`를 테스트 호스트에 연결하는 로컬 fixture 미리보기다. 질문 예시는 고정 문구이며 실제 LLM 동작이 아니다. 예시 상품·가격을 사용하고 실제 장바구니·결제·알림 API를 호출하지 않는다.

develop `ed978d9`에서 시작했고, 작업 중 Story 431이 병합되어 최신 develop `473c0df`로 rebase했다. 별도 모바일 앱·Core 결제 상태 전이는 변경하지 않는다. Story 431의 prepare_cart 복수 scope·인증 오류 처리·Core 판매처 병렬 조회를 보존하고 새 UI도 prepare_cart와 요청 제한·계측을 사용한다. 만료된 구매 요청은 최신 장바구니의 새 카드에서 새 요청으로 진행할 수 있다.

배포 후 ChatGPT 도구 새로고침, 새 대화에서 검색 → 상세 → 담기 → 장바구니 → 결제 요청 카드 생성, 재연결·권한 승격·오래된 카드의 버전 충돌을 별도로 확인한다. 로컬 시안만으로 실제 ChatGPT 동작을 완료 판정하지 않는다.
