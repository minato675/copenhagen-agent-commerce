Mock으로 검증한 기능은 그 수준으로만 기록한다. 실제 계약 검증이 끝나기 전에는 운영 연동 완료로 표시하지 않는다.
Core·Pay·Merchant·Mobile 구현은 담당 영역이며 MCP가 다른 모듈을 임의 수정하지 않는다.

## 결제 흐름과 책임

MCP 결제 진행 → Core 구매 인계 세션 → 모바일 앱 실행/로그인/소유권 확인 → 앱 배송지 선택
→ Core/Merchant 최종 checkout 검증 → Pay 승인 생성 및 앱 카드 선택 → 앱 지문/PIN 승인
→ 서버 결제·주문 → MCP 결과 조회.

- MCP: 인계 요청, 앱 열기, 대기 및 결과 조회.
- Mobile: 배송지·카드 선택 화면, 생체/PIN 처리, 로그인 후 복귀.
- Core/Pay/Merchant: 소유권·금액·재고·승인 검증과 실제 서버 상태 전이.
- 앱 열기와 승인 요청 생성은 결제 승인이 아니며, 승인 완료는 결제 성공과 구분한다.
- 앱 열기·세션 수신을 먼저 QA하고 선택/승인 통합을 이어서 QA한다.
- 단일 판매처 한 건부터 완성하고 다중 판매처의 집계·부분 실패 계약은 이후 확장한다.

개발 검증, ChatGPT 웹 검증, 사용자 Android 실기기 QA를 서로 구분한다.
