# 상품 이미지와 몰별 배송비 점검 (S15P21A207-447)

기준: develop 944b95f, 저장소의 merchant-a/b/c 데모 카탈로그. 운영 EC2 DB 또는 모든 CDN URL의 HTTP 가용성을 확인한 결과는 아니다.

## 이미지

세 몰 모두 1,408개 상품에 HTTPS 이미지 URL이 있다. 누락·잘못된 URL 형식은 0개다. 각 몰의 호스트 분포는 cdn.daisomall.co.kr 230개, img.danuri.io 494개, product-image.kurly.com 385개, 3p-image.kurly.com 264개, img-cf.kurly.com 35개이며 현재 MCP UI의 허용 호스트와 일치한다.

Merchant 응답에는 이미지가 있었지만 Core의 CatalogItem/CatalogProductDetail 수신 DTO, 내부 검색·상세 DTO 변환, 담기 시 상품 스냅샷에서 누락됐다. 이 경로를 연결하고 이미지가 없는 구형 제공자는 기존 null/빈 문자열 의미를 유지한다. 검색 비교 묶음은 첫 번째 비어 있지 않은 이미지를 사용한다. UI는 기존 정사각형 크롭과 실패 시 대체 표시를 사용한다.

기존 DB 장바구니 행에 이미 null로 저장된 이미지를 일괄 수정하지 않는다. 수정 이후 담기 또는 상품 스냅샷이 갱신되는 수량/옵션 변경부터 저장된다.

## 배송비

현재 설정은 기본 배송비 0원이며 도서산간 추가금만 있다. 상품별 배송비 필드는 없다. 배송지 없는 Catalog·장바구니 응답은 확정 배송비를 알 수 없어 null을 유지한다. 이 값을 무료배송으로 변환하거나 임의 가격으로 채우지 않는다.

OrderValidationService는 merchantId로 항목을 묶어 몰마다 주문서를 한 번 생성한다. Merchant CheckoutEvaluator는 모든 상품의 소계를 계산한 후 fulfillment 배송비를 한 번 더한다. 동일 몰의 상품 수·수량을 배송비에 곱하지 않는다. 서로 다른 몰은 각각의 주문서에 자신의 배송비를 한 번씩 부과한다.

회귀 예: 89,000원 상품 2개 + 27,000원 상품 3개 = 상품 259,000원. 테스트 기본 배송비 3,000원인 주문 합계는 262,000원이다. 실제 설정처럼 기본 배송비 0원에 제주 추가금 3,000원을 적용해도 합계는 262,000원이며 추가금 안내는 한 번이다.

배송비 중복 버그는 발견되지 않아 가격 산식을 바꾸지 않고 다품목 회귀 테스트를 추가했다. 최종 거래 금액은 기존과 같이 Merchant Checkout이 결정한다.
