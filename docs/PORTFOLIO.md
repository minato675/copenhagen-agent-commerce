# 포트폴리오 설명

## 개요와 역할

5인 팀의 AI 에이전트 기반 쇼핑·구매 서비스입니다. 팀 성과는 2026.10.02 SSAFY 특화프로젝트 2등입니다.
개인 담당은 MCP 구현과 이상거래 탐지 설계이며, `add_cart_item`을 대표 구현 사례로 사용합니다.
Codex 보조 구현을 수작업 단독 작성으로 바꾸어 설명하지 않습니다.

## 대표 사례: 장바구니 도구의 Core 응답 경계

- 상황: 에이전트가 판매처·상품·옵션·수량을 전달할 때, Core의 응답이 사용자와 요청에 일치하는지 확인해야 했습니다.
- 과제: MCP가 Core 도메인 로직을 중복 구현하지 않으면서 도구 결과의 형식과 연관 관계를 검증해야 했습니다.
- 행동: `CartToolConfiguration`, `CartService`, `CartSchemas`로 도구 등록·계약 변환·응답 검사를 구성하고 `CartServiceTest`와 Mock Core QA 기록으로 정상·오류 경계를 확인했습니다.
- 결과: QA3에 사용자 격리·요청 재시도·버전 충돌·동시 클릭 검증 기록이 있습니다. 이는 당시 Mock Core 확인 범위이며 실제 Core 저장·가격 계산·실결제 운영 성과를 뜻하지 않습니다.

## 기술 선택과 검증 범위

MCP는 Core 구현체 대신 계약을 사용하고 Core의 도메인 책임과 분리되어 있습니다.
도구 응답에 내부 오류 본문을 그대로 전달하지 않는 오류 경계가 문서화되어 있습니다.
당시 다른 프로토콜·라이브러리와 비교해 선택한 과정은 현재 자료만으로 확정하지 않습니다.
FDS는 설계·평가 자료와 실제 적용 범위를 구분해 설명해야 합니다. 탐지 정확도 향상이나 결제 사고 감소 수치를 새로 만들지 않습니다.

자료 기반 회고로 Keep은 입력·응답을 계약으로 검사하는 접근, Problem은 Mock과 실제 연동의 검증 범위를 구분해야 하는 점입니다.
향후 제안은 실제 Core 계약에 대한 실패·재시도 통합 시험 결과를 고정된 환경과 함께 정리하는 것입니다.
시각화는 에이전트 → MCP → Core의 입력·응답 검증 흐름도를 우선합니다.
