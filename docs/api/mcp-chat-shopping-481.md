# 채팅 중심 쇼핑 흐름 (Story 481)

## 사용자 이용 순서

1. “샌드위치 재료를 찾아서 담아줘”처럼 요청합니다.
2. 선택이 필요한 옵션과 수량은 채팅으로 답합니다. 자동 선택을 원하면 명시적으로 위임합니다.
3. 변경이 끝난 최종 장바구니 카드에서 상품·옵션·수량을 확인합니다.
4. 버튼 또는 “통밀식빵을 2개로 변경해줘”처럼 채팅으로 변경합니다.
5. 구매 요청 이후 실제 결제 승인은 앱에서 진행합니다.

### 구매내역 조회와 재구매 (Story 495)

- “최근 구매내역을 보여줘”, “전에 구매한 양파를 찾아줘”라고 요청합니다.
- 최근 6개월의 결제 완료 기록을 판매처·상품별로 확인합니다. 상품명, 최근 옵션·단가,
  구매 횟수, 총수량과 최근 구매일을 채팅으로 안내하며 별도 구매내역 카드를 만들지 않습니다.
- 한 번에 기본 20개, 최대 50개를 조회합니다. 다음 페이지가 있으면 “다음 구매내역도 보여줘”라고
  요청합니다. 첫 페이지에 상품이 없다는 이유만으로 전체 내역에 없다고 단정하지 않습니다.
- “이 양파를 다시 담아줘”라고 요청하면 현재 상품 상세에서 가격·재고·옵션을 다시 확인합니다.
  과거 상품 ID를 사용할 수 없으면 상품명으로 다시 검색하고, 후보가 여러 개면 선택을 요청합니다.
- 기록의 옵션과 단가는 과거 구매 시점 정보입니다. 옵션이 없거나 현재 옵션과 다르면 채팅에서
  선택하며, 구매내역 조회만으로 장바구니를 변경하거나 결제를 요청하지 않습니다.
- 내역이 없는 경우와 조회에 실패한 경우는 구분합니다. 조회 실패를 “구매한 적 없음”으로 안내하지 않습니다.
- `purchase:handoff` 권한이 필요합니다. 권한 부족 시 권한 동의 절차를 완료한 뒤 다시 조회합니다.
  SQL로 연결 권한이나 토큰을 직접 수정하지 않습니다.

구매내역 API 계약과 배포 검증은 [구매내역 MCP 연동](mcp-purchase-history-495.md)을 참고합니다.

## 도구 계약

- get_cart, prepare_cart, get_product_detail, 장바구니 변경 도구는 데이터 전용입니다.
- display_cart 및 display_product_detail만 최종 장바구니·상세 카드를 표시합니다.
- 여러 상품 담기 중 검색/중간 장바구니 카드를 호출하지 않습니다.
- add_cart_item은 selectionBasis(USER_SELECTED/USER_DELEGATED)가 필수입니다. MCP에서 검증 후 Core 계약에서 제외합니다.
- 이 필드는 모델이 전달하는 선택 근거이며 사용자 동의를 암호학적으로 증명하지 않습니다. 실제 질문 준수는 호스트 시나리오 검증 대상입니다.
- 상품 variant의 존재 여부 검증은 기존 Core captureForCart 경로를 유지합니다. 데이터가 기본 옵션만 제공하면 없는 옵션을 생성하지 않습니다.
- 버튼은 prepare_widget_action으로 선택을 보관하고 ui/update-model-context로 reference와 자연어 intent를 전달한 뒤 자연어 후속 메시지만 보냅니다.
- 컨텍스트 전송 실패 시 후속 메시지를 보내지 않습니다. 전송 확인은 모델의 실제 사용을 보장하지 않으므로 미전달·모호한 선택은 재선택 안내가 필요합니다.
- 계정의 가장 최근 선택을 임의로 사용하지 않습니다. 멱등키와 기존 선택은 재시도 때 유지합니다.

## 검증과 배포

로컬: MCP 전체 테스트와 Checkstyle, UI node --test src/*.test.js, node build.mjs --check.

배포 후에는 플러그인 도구 목록을 새로고침하고 새 대화에서 다음을 확인합니다.

- 초기화→6종 검색→옵션 질문→응답→담기에서 중간 카드가 없고 최종 카드 1회.
- 다중 카드와 오래된 카드에서도 상품·판매처·옵션·수량이 정확함.
- 연속 클릭 및 네트워크 결과 불명 시 중복 담기 없음.
- 컨텍스트 누락/만료 시 다른 상품을 추정하여 변경하지 않음.
- UI 메시지에 UUID/내부 JSON이 없고 할인 미확정 문구가 없음.
- 부분 실패 시 성공 항목과 미완료 항목을 구분함.
- 카드 수, 도구 호출 수, 첫 요청~최종 결과 시간을 동일 조건으로 비교함.

실제 ChatGPT의 배포 후 검증과 성능 전후 수치는 아직 확보되지 않았습니다. 로컬 테스트를 통과해도 이를 완료로 표시하지 않습니다.
